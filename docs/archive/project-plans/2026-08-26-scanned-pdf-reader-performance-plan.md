# 扫描版 PDF 阅读器性能优化方案

状态：已归档，进入执行阶段（2026-08-26）

配套原子任务：`docs/archive/project-plans/2026-08-26-scanned-pdf-reader-performance-atomic-tasks.md`

## 1. 背景与问题

阅读模式采用单个持久化 PDF `Document` 和连续页面列表。用户从目录跳转到尚未渲染的扫描页时，连续模式会以当前页为中心挂载前后各四页，最多同时创建九个 `Page`。每个页面当前还会创建文本层、独立调用 `getTextContent()` 判断页面类型，并把页面比例和文本类型逐页写回 `Books` 的 React 状态。

扫描版页面通常包含高分辨率位图。按照当前最高 1.5 倍设备像素比估算，一张常见 A4 页面 canvas 的 RGBA 缓冲约为 13 至 18 MB，九张页面仅 canvas 就可能达到 120 至 160 MB；图片解码缓冲、PDF.js 中间对象和 GPU 纹理不包含在内。远距离跳转会集中触发旧页面卸载、新页面解析、位图解码、canvas 绘制、文本提取、状态更新和垃圾回收，因此目录点击只是触发入口，不是主要耗时本身。

此前尝试过“先只渲染目标页，完成后再恢复邻页”的两阶段视图切换。该方案增加了额外状态提交和第二次负载峰值，实际体验退化，已经完整回退。本方案禁止重新引入同类的瞬时模式切换。

## 2. 目标与非目标

### 2.1 目标

- 目录点击后的交互确认和滚动定位不被 PDF 解码阻塞。
- 未缓存跳转中，目标页始终获得最高渲染优先级。
- 限制扫描页并发解码、canvas 内存和失效任务数量。
- 去除重复文本提取，缓存页面比例与文本模式。
- 返回近期页面时复用已完成结果，避免无意义的重复渲染。
- 用可复现指标证明改动有效，并保证普通文本 PDF、OCR、批注、自动阅读和三种布局模式不回归。

### 2.2 非目标

- 不更换 PDF.js/react-pdf 渲染引擎。
- 不在目录点击的冷路径上额外执行一次低清渲染后再执行高清渲染。
- 不预先渲染整本 PDF，也不使用无上限页面缓存。
- 不在缺少性能证据时重写整个 `Books` 页面或直接引入复杂虚拟列表库。
- 不以降低到不可接受的清晰度作为主要性能手段。

## 3. 当前性能瓶颈

### 3.1 P0：扫描图片解码与 canvas 绘制

扫描页的主要工作是解析页面操作、解码内嵌图片、缩放并绘制高分辨率 canvas。目录远跳时最多九页同时进入渲染窗口，造成 PDF worker、CPU、内存和 GPU 上传竞争。

### 3.2 P0：渲染任务并发和生命周期抖动

当前渲染窗口由 `currentPageIndex` 直接决定。远跳会在一次 React 提交中卸载旧窗口并挂载新窗口，目标页与邻页没有稳定的显式优先级。快速连续点击还会产生已经过期但正在执行或等待取消的任务。

### 3.3 P1：文本提取和文本层重复工作

`Page` 的文本层本身会获取文本内容，页面加载回调又调用一次 `page.getTextContent()`。纯图片页面的单次提取通常小于图片解码，但多页并发时会竞争 worker；带隐藏 OCR 文本的扫描页还会创建大量文本项和 DOM 节点。

### 3.4 P1：逐页 React 状态更新

页面比例和文本类型分别保存在 `Books` 状态中。九页首次挂载可能触发十多次对象复制、父组件渲染和完整页面数组遍历，放大主线程压力。

### 3.5 P1：已完成页面缺少受控复用

页面离开渲染窗口后 canvas 被销毁。用户在章节之间往返时可能重复执行页面解析、位图解码、canvas 绘制和文本提取。

### 3.6 P2：伪虚拟化与估算高度

远页虽然是占位符，但每页仍保留一个 DOM 节点。长文档每次更新都会遍历完整列表。跳转位置依赖估算高度，真实页面比例写回后可能产生布局位移。该项只有在测量证明占比明显后才进入结构性改造。

### 3.7 P3：目录树联动

目录选中会触发祖先展开、树更新和 `scrollIntoView`。它会增加布局工作，但预计小于 PDF 位图路径，应通过数据验证而不是优先重构。

## 4. 高风险操作场景

1. 从目录远距离跳转到尚未渲染的扫描页。
2. 快速连续点击多个目录节点。
3. 在渲染窗口之外的章节间反复往返。
4. 调整窗口宽度或切换单页、双页、连续布局，使 canvas 尺寸失效。
5. 打开带大量隐藏 OCR 文本的扫描 PDF。
6. 在页面渲染期间同时触发 OCR、批注恢复或自动阅读预取。
7. 打开数百页以上或页面尺寸不统一的 PDF。

## 5. 目标架构

```text
目录点击
  -> 立即提交导航位置和交互反馈
  -> 记录一次 jump trace
  -> 稳定渲染调度器
       1. 可见目标页
       2. 当前视口内其他页
       3. 阅读方向上的邻页
       4. 反方向邻页与空闲预热
  -> 页面本地读取/写入元数据缓存
  -> 单一文本提取结果完成文本层和页面类型判断
  -> canvas 完成后进入受内存预算约束的近期页面缓存
```

导航状态、渲染准入状态和页面元数据必须分离。渲染调度器只能增加或淘汰稳定页面集合，不通过“目标页模式/普通模式”切换重建同一个目标页。

## 6. 优化策略

### 6.1 可观测性优先

为目录跳转建立有界、会话级、无用户内容的性能记录，至少包含：点击确认、滚动定位、页面加载、canvas 完成、文本提取完成、过期跳转和同时准入页面数。记录使用单调时钟，测试中可注入时钟，不持久化书名、路径、目录标题或文本内容。

### 6.2 单一文本提取路径

使用 react-pdf 文本层的成功回调提供 `TextContent`，页面类型判断不再独立调用 `getTextContent()`。页面模式按当前书籍会话和页码缓存。已知扫描页重新挂载时跳过 PDF 文本层，保留按需 OCR 选择能力；文本页继续提供原生选择。

### 6.3 页面元数据缓存与局部更新

页面比例和文本模式进入文档会话级缓存。页面槽订阅自身元数据或使用本地状态，避免一个页面加载导致整个连续列表和 `Books` 重渲染。布局模式仍可读取缓存计算占位高度，书籍切换时原子清空会话缓存。

### 6.4 稳定的优先级渲染队列

引入纯函数调度模型，按目标页、可见页、方向邻页排序，并限制一次新准入的页面数。目录远跳时保留目标页稳定 key；快速连续点击只丢弃尚未开始的过期候选，不主动重建已完成目标页。自动阅读使用相同调度器，通过阅读方向提高前向页面优先级。

### 6.5 内存预算缓存

缓存近期已完成页面的挂载资格，使用估算像素字节而不是固定页数控制预算。当前可见页和当前目标页不可被淘汰；其他页面按最近使用顺序淘汰。窗口缩放导致渲染宽度变化时，旧尺寸页面不得冒充有效高清结果。

若后续引入低分辨率预览，只允许在应用空闲期为高价值目录目标生成，并使用独立的小预算缓存；目录点击冷路径不得追加低清和高清两次完整解码。

### 6.6 证据驱动的真正虚拟化

只有当性能记录证明“完整占位列表遍历/布局”已经成为显著瓶颈，才把列表改为有限页面窗口加上下 spacer，并维护累计高度索引。页面尺寸缓存必须先于该改造完成，以保证远距离目录跳转的定位准确性。

## 7. 验证方法

每个原子任务均需通过：

- 对应纯函数、组件契约或集成测试。
- `npm test`。
- `npm run lint`。
- `npm run build`。
- `git diff --check`。

性能验证使用同一设备、同一窗口尺寸和固定样本，分别记录纯扫描、隐藏 OCR、普通文本、混合 PDF 的冷跳转、热跳转、连续快速跳转和窗口调整。相对基线至少关注：

- 目标页 canvas 完成时间的 P50/P95。
- 点击后 50 ms 内是否完成交互确认与滚动提交。
- 单次跳转启动和取消的页面任务数。
- 主线程长任务数量。
- 跳转前后峰值内存及返回近期页面是否重新渲染。

绝对高清完成时间受 PDF 编码和设备影响，不在缺少基线时承诺统一毫秒值。

## 8. 风险与回退边界

- 错误地关闭文本层会破坏文本选择，因此只有缓存明确为扫描页时才跳过文本层。
- 缓存能降低重复渲染，但可能提高常驻内存，必须先有预算和淘汰测试。
- 调度器若通过反复变更 `Page` key 实现，会重新引入任务抖动，评审时必须拒绝。
- 真正虚拟化会影响滚动位置、批注定位和自动阅读，只能作为最后阶段、独立提交实施。
- 任一阶段若同样测试样本的目标页完成时间或交互延迟明显退化，应回退该阶段提交，而不是继续叠加补丁掩盖问题。
