# 扫描版 PDF 阅读器空闲预取与不对称窗口方案

状态：已归档，待按原子任务执行（2026-08-26）

配套原子任务：[2026-08-26-scanned-pdf-reader-idle-prefetch-atomic-tasks.md](./2026-08-26-scanned-pdf-reader-idle-prefetch-atomic-tasks.md)

## 1. 背景与问题

上一轮性能改造已经完成目标页优先、最多两页在途、文本层结果复用、页面元数据隔离和受预算约束的近期页面保留。但连续滚动仍然会在 `currentPageIndex` 变化后推进渲染窗口，滚动尚未稳定时就可能开始邻页挂载、Canvas 预渲染和未知页文本层初始化。

对扫描版 PDF 而言，快速滚动期间的邻页工作很容易在用户真正停留前失效。文本层初始化可能触发 PDF.js 文本提取，页面预渲染还会竞争图片解码、Canvas 绘制、主线程和内存。当前实现的并发上限只能限制同时在途数量，不能消除滚动期间已经失效的候选工作。

## 2. 目标与非目标

### 2.1 目标

- 滚动进行中立即更新当前页和页码信息，不等待候选页工作。
- 用户停止滚动 400ms 后，再启动候选页预取和未知页文本层判断。
- 新滚动开始时取消或淘汰上一轮尚未完成的候选任务，旧结果不得污染当前状态。
- 默认候选窗口改为当前页前 1 页、后 3 页，最多 5 页。
- 候选优先级固定为当前页、后续页、前置页，符合按页码递增阅读的主要习惯。
- 已缓存的页面元数据、渲染结果和 OCR 结果继续复用。
- 保持目录跳转、单页/双页模式、自动阅读、文本选择、批注和显式 OCR 行为不回归。

### 2.2 非目标

- 不更换 PDF.js 或 react-pdf 渲染引擎。
- 不在目录点击冷路径增加低清预览再高清渲染的两阶段负载。
- 不把当前页必要的 Canvas 显示延迟到 400ms 之后。
- 不让显式 OCR、批注恢复或目录 OCR 等用户主动操作等待滚动空闲计时器。
- 不在本方案中实施高风险的完整列表虚拟化。

## 3. 设计原则

### 3.1 即时路径与后台路径分离

滚动期间只处理用户能直接感知的导航状态：当前页索引、阅读进度、滚动定位和当前页必要渲染。候选页的文本层、页面类型判断和邻页预取属于后台路径，必须等滚动稳定后再进入队列。

### 3.2 固定不对称候选窗口

连续模式默认使用：

```text
前 1 页 + 当前页 + 后 3 页
```

例如当前为第 99 页，候选集合为第 98～102 页。文档首尾按页数裁剪。目标页和当前可见页仍然拥有最高优先级，随后依次处理第 100、101、102 页，最后处理第 98 页。

### 3.3 400ms 空闲门槛

每次 PDF 连续滚动事件都将阅读器标记为 `scrolling`，清理上一轮空闲计时器并取消未完成的候选准入。最后一次滚动事件之后 400ms，阅读器进入 `settled`，才允许候选窗口恢复。

页码和进度信息仍按现有的短延迟节流及时更新；400ms 只约束候选后台工作，不约束导航反馈。

### 3.4 可取消且结果隔离

每一轮候选工作使用递增代次。新滚动开始时使旧代次失效，并通过调度窗口收缩、组件卸载和现有 PDF.js 任务清理尽快停止旧邻页。异步回调提交结果前必须验证当前会话和任务代次，过期结果只能被丢弃。

`getTextContent()` 已进入 PDF.js 内部后不保证同步中止，因此取消的硬要求是阻止后续候选扩散和阻止过期结果更新；下一轮必须复用已完成缓存。

### 3.5 文本层安全门

滚动未稳定时，未知页面不得创建文本层，从而避免在滚动期间隐式触发 `getTextContent()`。已缓存为普通文本的页面继续显示文本层；已缓存为扫描页的页面继续关闭文本层。进入 `settled` 后，未知页面才允许通过 react-pdf 的 `onGetTextSuccess` 完成一次文本模式判断。

## 4. 目标流程

```text
滚动事件
  -> 立即更新当前页引用与页码节流
  -> 清除 400ms 空闲计时器
  -> 取消/收缩旧候选调度窗口
  -> 当前页保持必要 Canvas 显示，未知页关闭文本层

停止滚动 400ms
  -> 标记 settled
  -> 建立前 1、后 3 的候选优先级
  -> 当前页优先，随后后续页，再前置页
  -> 逐步执行并缓存文本模式与渲染结果
```

目录远跳仍然立即提交目标页和滚动位置；目标页不等待 400ms 才显示。远跳后的邻页预取遵循同一空闲门槛，避免连续点击时累积失效任务。

## 5. 验收标准

- 当前页为第 99 页时，默认候选集合为 `[98, 99, 100, 101, 102]`，越界页被裁剪。
- 滚动期间候选集合最多只包含当前目标页及必要的可见页，不启动邻页预取。
- 滚动期间未知页不会新建文本层或触发由页面渲染路径产生的 `getTextContent()`。
- 最后一次滚动事件后不足 400ms 再次滚动，旧计时器和旧候选工作失效。
- 停止 400ms 后才恢复候选调度；当前页始终优先。
- 已完成页面和已缓存文本模式不重复执行。
- 显式 OCR、目录 OCR、批注恢复和文本页选择不被空闲门槛阻塞。
- 连续模式、单页模式、双页模式、自动阅读、目录跳转和窗口缩放通过现有测试与新增回归测试。

## 6. 风险与回退边界

- 若滚动期间关闭当前未知页文本层的逻辑错误地影响普通文本页选择，应立即回退该门控，只保留候选窗口和调度取消改动。
- 若 400ms 导致停留后的文本选择或批注交互感知延迟，应把门控范围限制到邻页，当前页在稳定后优先即时处理。
- 若 PDF.js 对卸载任务的取消不完整，必须依靠任务代次检查阻止过期状态提交，不得通过更换 `Page` key 强制重建。
- 候选页从 9 页降为 5 页会降低反向阅读的预热程度，这是按主要顺序阅读习惯做出的明确取舍。
