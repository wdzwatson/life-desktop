# C-01-02 搜索状态与查询竞态

日期：2026-08-20  
状态：已归档，待执行  
所属计划：[C-01 全局搜索原子任务计划](2026-08-20-c01-global-search-atomic-tasks.md)

## 目标

让搜索 UI 正确区分空闲、加载、成功、无结果、部分失败和完全失败，并保证旧请求不会覆盖新查询。

## 实现步骤

1. 建立搜索状态类型：`idle`、`loading`、`ready`、`empty`、`partial-error`、`error`。
2. 为每次查询分配 request ID，结果提交前校验仍是最新请求；可行时增加取消机制。
3. 并行执行四类查询或将查询集中到统一服务。
4. 保存模块级错误信息，部分失败时保留成功模块结果。
5. 增加加载、空结果、失败和重试文案。

## 验收标准

- 输入变化后旧结果不能回退覆盖新结果。
- 加载期间不显示无结果文案。
- 单模块失败时其余结果仍可操作，并显示失败范围。
- 全部失败时显示错误和重试入口。
- 空查询显示引导，不执行无意义查询。

## 测试证据

- 延迟交错请求测试。
- 单模块失败、全部失败、重试和空查询测试。
- 检查无未处理 Promise rejection。

## 风险

取消请求若无法跨 Electron IPC 边界实现，必须至少使用 request ID 防止过期结果提交。
