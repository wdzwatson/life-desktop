# C-01-05 隐私边界与全文检索演进

日期：2026-08-20  
状态：已完成，已归档
所属计划：[C-01 全局搜索原子任务计划](2026-08-20-c01-global-search-atomic-tasks.md)

## 目标

在不泄露私密笔记的前提下，评估并逐步将当前 `LIKE` 查询演进为可排序、可摘要的全文检索。

## 实现步骤

1. 明确锁定私密笔记策略，默认不显示可识别标题、正文或片段。
2. 盘点现有 `notes_fts` 触发器、字段和更新路径。
3. 设计任务、笔记、书籍、视频统一索引或分模块 FTS 的边界、迁移和回退。
4. 若风险可控，实现 snippet/highlight 和相关性排序；否则交付技术决策与性能基线，统一索引延期。
5. 确认日志、缓存和 DOM 不保存不必要的私密内容。

## 验收标准

- 锁定私密笔记不会出现在结果、摘要、日志或缓存中。
- FTS 结果相关性不低于现有 LIKE 查询。
- 索引更新、重建和失败回退行为有证据。
- 常用数据规模下 P95 首结果小于 300ms，或记录明确性能缺口。

## 测试证据

- 私密/非私密笔记测试。
- 中文文本、特殊字符和索引重建测试。
- 性能样本与结果对比。

## 完成证据

- 全局搜索 SQL 在标题和正文匹配前统一要求 `COALESCE(is_private, 0) = 0`，私密笔记不会进入结果、摘要或 DOM。
- `notes_fts` 已重建为仅索引公开笔记；插入、删除以及公开/私密状态切换均由带隐私条件的触发器维护。
- 统一四模块 FTS 暂不迁移：当前 LIKE 查询已具备稳定性能基线，中文分词、snippet 语义和跨库回退需另立迁移任务验证。
- Electron 原生测试覆盖私密索引重建、状态切换、SQL 隐私回归及 10,000 条笔记 P95 性能；`npx tsc --noEmit -p tsconfig.app.json`、定向 ESLint 和 `npm run build` 通过。
