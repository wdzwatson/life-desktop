## 一、执行原则

- 每个任务只有一个主要交付结果，可独立开发和验收。
- P1 任务先完成搜索闭环；P2 任务改善相关性、隐私和规模能力。
- 任务完成必须有代码、测试或验收证据；只有文档记录不能标记为实现完成。
- 工具箱不纳入本轮全局搜索。

## 三、任务详情

### C-01-01 搜索结果模型与精确定位

- 负责人：前端开发，必要时协同各模块开发。
- 优先级：P1。
- 依赖：无。
- 输入：`src/App.tsx`、`src/views/Tasks.tsx`、`src/views/Notes.tsx`、`src/views/Books.tsx`、`src/views/Videos.tsx`。
- 动作：定义统一 `GlobalSearchResult`；查询结果携带实体 ID、模块和可选匹配字段；实现任务详情、指定笔记、指定书籍阅读器、指定视频详情的打开动作。
- 交付物：统一类型和导航适配；必要的模块 deep-link 事件或 store 状态。
- 验收：四类结果点击后直接打开对应对象；搜索面板关闭；对象不存在时有可理解的回退提示；不通过标题二次查找。
- 测试：每类至少一个结果定位测试；覆盖无效 ID。

### C-01-02 搜索状态与查询竞态

- 负责人：前端开发。
- 优先级：P1。
- 依赖：无。
- 输入：`src/App.tsx` 查询 effect。
- 动作：引入 `idle/loading/ready/empty/partial-error/error` 状态；四类查询并行执行或集中到统一服务；用请求序号或取消机制防止旧结果覆盖新结果；为模块失败提供重试或降级反馈。
- 交付物：状态模型、查询执行器、错误文案和状态 UI。
- 验收：快速输入只提交最新请求；加载时不显示空结果；单模块失败不会吞掉其他模块结果；全部失败显示错误和重试入口。
- 测试：模拟延迟交错、单模块失败、全部失败和空查询。

### C-01-03 键盘导航与可访问性

- 负责人：前端开发 + QA。
- 优先级：P1。
- 依赖：C-01-01。
- 输入：命令面板 JSX、`src/components/Topbar.tsx`、`src/index.css`。
- 动作：将搜索弹层建模为 combobox/listbox/option；增加结果 active 状态、ArrowUp/ArrowDown、Home/End、Enter、Esc；设置稳定 aria-label；关闭后恢复触发按钮焦点；校正窄窗口布局。
- 交付物：键盘交互、ARIA 语义、响应式样式和中英文文案。
- 验收：无需鼠标可打开、选择、执行和关闭；屏幕阅读器可识别入口、输入框和当前结果；390px 下无横向溢出。
- 测试：键盘路径、焦点恢复、无名称按钮检查、窄窗口截图/DOM 检查。

### C-01-04 相关性排序与结果呈现

- 负责人：前端开发，必要时协同 Electron 数据层。
- 优先级：P1。
- 依赖：C-01-01、C-01-02。
- 输入：四类查询 SQL、结果列表 UI、现有时间字段。
- 动作：实现标题完整/前缀/包含/其他字段的确定性评分；同分按更新时间排序；按模块分组并显示计数；显示匹配字段、摘要或“查看全部”。
- 交付物：排序函数、结果分组 UI、结果摘要文案。
- 验收：同一数据集排序稳定；标题精确匹配优先；用户能看出命中原因；超过展示上限时可进入对应模块查看完整结果。
- 测试：排序边界、空字段、相同分数、模块计数和截断提示。

### C-01-05 隐私边界与全文检索演进

- 负责人：Electron / 数据层开发 + 产品经理。
- 优先级：P2。
- 依赖：C-01-02。
- 输入：`electron/db/schema.ts` 的 `notes_fts`、笔记私密字段、搜索查询。
- 动作：明确锁定私密笔记的产品策略并实现；评估或实现任务、笔记、书籍、视频的 FTS 统一索引；返回 snippet/highlight；记录迁移、索引更新和失败回退方案。
- 交付物：隐私策略实现；FTS 技术决策或最小可用实现；性能基线。
- 验收：锁定私密笔记不泄露标题、正文、片段或日志；FTS 结果相关性不低于现有 LIKE；索引失败有安全回退；常用规模 P95 首结果小于 300ms。
- 测试：私密/非私密、索引更新、重建、中文文本、特殊字符和性能样本。

### C-01-06 全局搜索验收与指标

- 负责人：QA + 产品经理。
- 优先级：P1。
- 依赖：C-01-01 至 C-01-05。
- 输入：产品方案验收标准、实现任务交付物。
- 动作：建立搜索验收矩阵；覆盖桌面、390px 窄窗口、中文/英文、鼠标/键盘、空/错误/部分错误、私密笔记和四类对象定位；定义耗时、零结果率、点击率、模块命中率、失败率指标采集方式。
- 交付物：自动化测试、人工验收记录、指标字段和已知风险清单。
- 验收：所有 P1 标准均有通过证据；失败项有缺陷等级和处理决定；指标能区分查询开始、首结果、结果点击和查询失败。
- 测试：`npm test`、`npm run build`、`npm run lint`，以及本地桌面/窄窗口交互验收。

## 五、完成定义

一个任务只有同时满足以下条件才可标记为完成：

- 代码或决策文档已落位，且未引入未记录的范围扩张。
- 相关自动化测试或人工验收证据已记录。
- 中英文文案和基础可访问性已覆盖。
- 成功、空结果、失败和边界路径均有处理。
- 对数据隐私、性能和后续限制有明确记录。

## 六、风险与延期策略

- 若无法在本轮稳定实现跨模块 deep-link，先保留模块跳转但必须显示“已定位到模块，需手动选择”的降级提示，并不得标记 C-01-01 完成。
- 若 FTS 索引迁移风险高，C-01-05 可拆为先完成私密策略和性能评估，统一索引延期；P1 搜索闭环不因 FTS 阻塞。
- 若工具箱后续形成实体模型，应新建范围决策任务，不直接扩大本计划。
