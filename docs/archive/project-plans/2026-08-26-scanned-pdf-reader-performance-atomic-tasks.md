# 扫描版 PDF 阅读器性能优化原子任务清单

日期：2026-08-26  
状态：已归档，执行中  
来源：[扫描版 PDF 阅读器性能优化方案](./2026-08-26-scanned-pdf-reader-performance-plan.md)

## 一、执行原则

- 每个任务只有一个主要性能目标，必须独立审查、验证和提交。
- 每项任务开始前确认工作区只包含预期改动，完成后执行针对性测试、全量测试、lint、build 和 diff 检查。
- 不以主观“感觉更快”代替分段数据；不以降低核心阅读能力换取指标。
- 禁止重新引入“只渲染目标页，再切换回邻页”的两阶段视图模式。
- 任务完成记录必须写明提交、验证证据、已知风险和下一项依赖。

## 三、原子任务详情

### PDF-PERF-01 目录跳转性能观测基础

目标：在不改变页面准入和渲染行为的前提下，能够区分目录交互、滚动、PDF 页面加载、canvas 绘制和文本提取耗时。

范围：

- 新增无用户内容、会话级、有界的 PDF 阅读器性能 trace 服务。
- 目录选择生成 jump ID；目标页面回调关联当前有效 jump。
- 记录 `outline-select`、`scroll-committed`、`page-loaded`、`canvas-rendered`、`text-resolved` 和 `superseded`。
- 提供只读快照用于测试和开发诊断，不写数据库或遥测端点。
- 使用可注入单调时钟测试时序、容量上限和过期跳转。

验收：

- 指标不包含书名、路径、目录标题、选中文本和 OCR 内容。
- 快速连续跳转时旧 jump 被标记为过期，新 jump 不接收旧页面完成事件。
- 正常阅读路径没有新增 React 状态更新。

验证：针对性测试、`npm test`、`npm run lint`、`npm run build`、`git diff --check`。

完成记录：

- 完成日期：2026-08-26。
- 提交：本任务独立提交（见 Git 历史）。
- 结果：新增有界 `PdfReaderPerformanceTrace`，把目录选择、滚动提交、目标页加载、canvas 完成、文本完成和跳转失效关联到同一个数值 jump；书籍会话切换时原子清空，不写数据库或外部遥测。
- 审查：trace 不包含书名、路径、目录标题、文本或 OCR 内容，不进入 React state，也未改变页面准入、DPR、文本层或布局行为；旧 jump ID 和非目标页回调均被拒绝。
- 验证：3 项 trace 针对性测试和 24 项阅读器呈现契约测试通过；`npm test`、`npm run lint`、`npx tsc -b --pretty false`、`npm run build`、`git diff --check` 通过。
- 风险/后续：当前快照是会话内开发诊断数据，没有面向用户的遥测展示；PDF-PERF-02 将复用 `text-resolved` 节点验证文本提取去重。

### PDF-PERF-02 单一文本提取与文本模式缓存

目标：删除页面类型判断对 `page.getTextContent()` 的重复调用，并避免已知扫描页重挂载时再次创建 PDF 文本层。

范围：

- 通过 react-pdf `onGetTextSuccess` 接收文本层已取得的 `TextContent`。
- 用纯函数根据文本项计算 `text/scanned`，覆盖空项、空白项、隐藏 OCR 和异常。
- 文本提取失败时降级为扫描页并保留 OCR 入口。
- 页面模式在当前书籍会话中按页缓存；已知扫描页重挂载时设置 `renderTextLayer={false}`。
- 单页、双页和连续模式使用同一判断函数。

验收：

- `Books.tsx` 页面加载回调不再直接调用 `page.getTextContent()`。
- 普通文本 PDF 保持可选择；扫描页 OCR 选择层保持可用。
- 同一会话内已知扫描页离开并返回时不再启动 PDF 文本层。

验证：文本模式单元测试、阅读器契约测试、全量门禁。

完成记录：

- 完成日期：2026-08-26。
- 提交：本任务独立提交（见 Git 历史）。
- 结果：页面类型判断改为复用 react-pdf `onGetTextSuccess` 提供的 `TextContent`，删除页面挂载回调中的第二次 `getTextContent()`；文本模式在当前书籍会话内按页保存，已知扫描页重挂载时不再创建 PDF 文本层。
- 审查：普通文本和隐藏 OCR 页面在累计两个有效字符后保留原生文本层；空白、无文本和提取失败页面降级为扫描页，OCR 墨迹选择和批注覆盖保持不变。后台修复损坏目录标题的独立文本读取不属于页面渲染路径，按原行为保留。
- 验证：4 项文本模式/源码契约测试和 3 项性能 trace 测试通过；`npm test`、`npm run lint`、`npx tsc -b --pretty false`、`npm run build`、`git diff --check` 通过。
- 风险/后续：首次未知页面仍需完成一次文本层读取才能安全分类；PDF-PERF-03 将把比例和模式移入会话级按页缓存，消除逐页父状态更新。

### PDF-PERF-03 页面元数据缓存与局部状态隔离

目标：一个页面的比例或文本模式完成时，只更新该页面槽及必要覆盖层，不驱动整个 `Books` 和完整连续列表逐页重渲染。

范围：

- 建立文档会话级 `PdfPageMetadataCache`，包含比例、文本模式和版本边界。
- 页面槽使用局部状态或按页订阅读取元数据。
- 书籍切换时清空旧会话，旧异步回调不得污染新文档。
- 占位页和分页布局继续读取已缓存比例。
- 删除 `Books` 中仅为逐页回写服务的对象状态及对应 memo 比较。

验收：

- 单页元数据更新不会改变其他页面槽的订阅快照。
- 九页完成不会产生九次完整列表对象复制。
- 页面比例变化后目录定位和批注覆盖层尺寸仍正确。

验证：缓存/订阅测试、会话隔离测试、阅读器契约测试、全量门禁。

完成记录：

- 完成日期：2026-08-26。
- 提交：本任务独立提交（见 Git 历史）。
- 结果：新增文档会话级 `PdfPageMetadataCache`，连续列表拆为 memoized 页面槽，每个槽通过 `useSyncExternalStore` 只订阅自身页码；比例、文本模式和扫描墨迹启用状态在页面局部更新，不再维护或复制全局页面比例对象。
- 审查：缓存快照在无变化时保持引用稳定，写入只通知对应页；书籍切换递增 session 并清空缓存，旧 Page 回调因 session 不匹配被拒绝。分页布局切换时会读取同一缓存，并继续用局部分页状态接收首次文本结果。
- 验证：4 项缓存/结构契约测试、4 项文本模式测试和 24 项阅读器呈现契约测试通过；`npm test`、`npm run lint`、`npx tsc -b --pretty false`、`npm run build`、`git diff --check` 通过。
- 风险/后续：长文档仍保留每页一个轻量订阅和占位节点；PDF-PERF-04 将先解决重页面准入并发，完整列表成本留到最终证据门禁判断。

### PDF-PERF-04 稳定的目标页优先渲染调度器

目标：目录远跳时优先准入目标页，限制同时新增的重渲染页面，并避免通过两阶段模式切换重建目标页。

范围：

- 抽出纯函数调度器，输入文档页数、目标页、可见页、阅读方向、已准入页和已完成页。
- 输出稳定有序的准入集合；目标页优先，其次可见页、前向邻页和反向邻页。
- 扫描/未知页面采用保守并发上限；文本页可使用测量后确认的较宽上限。
- 快速连续目录点击时只清理未开始的过期候选，目标页 key 和已完成页面保持稳定。
- 自动阅读与手动滚动复用调度模型，不引入另一套窗口切换逻辑。

验收：

- 目标页始终是远跳后的第一个新准入页面。
- 连续点击不会累积无上限候选；完成页面不会因优先级变化被重建。
- 调度状态变化次数和同时渲染数可由 PDF-PERF-01 指标确认。

验证：优先级、边界、连续点击和自动阅读测试；全量门禁。

完成记录：

- 完成日期：2026-08-26。
- 提交：本任务独立提交（见 Git 历史）。
- 结果：新增目标页优先的 `PdfPageRenderScheduler`，远跳先单独准入目标页，页面加载后再开放第二个槽位；后续每次完成或失败只补入一个候选，手动滚动和自动阅读共用同一调度模型。
- 审查：目标页、当前可见页及阅读方向邻页按稳定顺序排队，同时在途页面始终不超过 2；相邻窗口保留重叠完成页，远跳清除过期未完成项，失败页释放槽位且不会无限重试。连续列表按文档会话重建调度器，未引入先渲染目标再整批恢复邻页的两阶段模式。
- 验证：5 项调度器优先级、边界、并发、连续跳转和失败恢复测试通过；`npm test`、`npm run lint`、`npx tsc -b --pretty false`、`npm run build`、`git diff --check` 通过。
- 风险/后续：当前只在活动窗口内保留完成页面；PDF-PERF-05 将增加有明确像素预算和保护页规则的近期页面保留。

### PDF-PERF-05 内存受控的近期页面保留

目标：提高章节往返命中率，同时确保 canvas 常驻内存存在明确上限。

范围：

- 新增按估算 canvas 像素字节计费的 LRU 保留模型。
- 当前目标页、可见页和正在交互的 OCR/批注页不可淘汰。
- 页面完成后进入近期集合；超预算时按最近使用顺序淘汰非保护页。
- 渲染宽度、DPR 或文档会话变化时，使不兼容缓存失效。
- 不缓存用户文本内容，不把高分辨率 canvas 持久化到数据库。

验收：

- 重复目录往返能复用预算内页面。
- 任意任务序列下估算缓存字节不超过预算，保护页例外必须可解释且短暂。
- 缩放后不会显示旧尺寸页面作为最终高清结果。

验证：LRU 顺序、预算、保护页和尺寸失效测试；全量门禁。

完成记录：

- 完成日期：2026-08-26。
- 提交：本任务独立提交（见 Git 历史）。
- 结果：新增独立的 `PdfPageRenderCache`，按渲染宽度、页面比例、DPR 和 RGBA 像素估算 canvas 字节，以 96 MiB 预算保留近期完成页面；调度器只挂载 LRU 决定保留的完成页，预算淘汰后不会在当前窗口循环重渲染。
- 审查：目标页、当前可见页、OCR 处理中页面、手写选择页和当前批注页受保护；保护页造成的临时超预算以 `protectedOverflowBytes` 明确暴露，保护解除后立即按 LRU 回收。文档会话、渲染宽度或 DPR 通过兼容性键失效，不保存 canvas、文本、OCR 内容或任何数据库记录。
- 验证：4 项像素估算、LRU、保护溢出和兼容性失效测试，7 项调度器保留/往返/淘汰测试及 24 项阅读器呈现契约测试通过；`npm test`、`npm run lint`、`npx tsc -b --pretty false`、`npm run build`、`git diff --check` 通过。
- 风险/后续：预算是基于 canvas RGBA 像素的保守估算，不包含浏览器/PDF.js 内部对象；PDF-PERF-06 将结合结构基准判断完整占位列表是否值得承担虚拟化风险。

### PDF-PERF-06 虚拟化决策与完整性能回归

目标：依据前五项指标决定是否实施真正虚拟化，并完成扫描版 PDF 性能交付验收。

范围：

- 使用固定样本记录纯扫描、隐藏 OCR、普通文本和混合 PDF 的冷跳转、热跳转、连续跳转和窗口调整。
- 比较完整页列表遍历/布局与 PDF 解码/canvas 的占比。
- 若列表成本已是显著瓶颈，实现有限页面窗口、上下 spacer 和累计高度索引；否则记录不实施决定，避免高风险无收益改造。
- 验证目录定位、滚动同步、自动阅读、OCR、批注、单页、双页和连续模式。
- 在 `docs/archive/qa/` 归档最终结果、环境、命令、指标和遗留风险。

验收：

- 有明确数据支持“实施”或“不实施”虚拟化的决定。
- 目录跳转期间目标页优先、任务数量受控、近期页面可复用。
- 所有现有自动化测试、lint 和生产构建通过。

验证：针对性性能测试、`npm test`、`npm run lint`、`npm run build`、`git diff --check`。

完成记录：

- 完成日期：2026-08-26。
- 提交：本任务独立提交（见 Git 历史）。
- 结果：补齐纯扫描、隐藏 OCR、普通文本和混合 PDF 固定样本，新增可重复的 PDF.js 页面阶段与 320 页 DOM 结构基准，并在 `docs/archive/qa/2026-08-26-scanned-pdf-reader-performance-validation.md` 归档完整指标和验收结果。
- 审查：目录定位结构 P95 为 0.10 ms，仅占帧预算 0.625% 和最轻冷页面阶段 2.00%；宽度重排 P95 为 1.80 ms，占帧预算 11.25%。三个预设阈值均未触发，因此依据数据不实施高风险虚拟化，保留完整轻量页槽和已完成的重页面准入/缓存控制。
- 验证：虚拟化决策、基准资产、四类 fixture、trace、文本模式、元数据、调度器、LRU 和阅读器呈现针对性测试通过；`npm test`、`npm run lint`、`npx tsc -b --pretty false`、`npm run build`、`git diff --check` 通过。
- 风险/后续：DOM 微基准不替代真实用户设备端到端 trace，PDF.js operator list 也是 canvas 完成的保守下界；若生产数据越过归档阈值，再以有限窗口方案开启新的独立任务。
