# C-01 全局搜索产品方案

日期：2026-08-20  
方案状态：已归档，待执行  
目标版本：下一轮搜索体验收口版本  
来源：顶部搜索代码审查、产品进展评估与本地页面验收

## 一、产品结论

顶部搜索已经覆盖任务、笔记、书籍和视频，但当前定位仍是“跨模块快速入口”，尚未形成完整的搜索闭环。用户可以看到匹配项，却不能稳定、直接地打开命中的具体对象；键盘操作、加载状态、失败反馈和结果相关性也不完整。

本轮目标不是扩大搜索范围，而是让现有范围可靠可用：

- 搜索结果可直接定位到具体任务、笔记、书籍和视频。
- 鼠标、键盘和辅助技术拥有一致的操作路径。
- 搜索状态能区分加载中、无结果、部分失败和成功。
- 查询结果稳定、相关、可解释，且不会被旧请求覆盖。
- 私密内容不会因全局搜索泄露。

工具箱暂不纳入全局搜索。工具箱当前是静态面板入口，没有统一可检索实体、持久化名称和结果定位模型；继续扩大承诺会制造产品范围与实现不一致。

## 二、现状与证据

实现集中在 `src/App.tsx` 和 `src/components/Topbar.tsx`：

- 查询任务、笔记、书籍、视频四个数据库；每类结果固定数量，查询没有统一排序或相关性评分。
- 结果点击只切换模块，不携带并使用任务、笔记、书籍或视频 ID。
- 结果项是普通 `div`，没有 listbox/option 语义，也没有上下键和 Enter 导航。
- 四类查询串行执行；没有请求序号或取消机制，快速输入存在旧结果覆盖新结果的风险。
- 查询失败被静默忽略；加载中、空查询和无结果共用近似状态。
- 关闭搜索后关键词仍保留；重新打开会恢复上一次关键词。
- 窄窗口隐藏搜索按钮文字和快捷键，按钮缺少稳定的可访问名称。
- 笔记正文查询已排除私密内容，但私密笔记标题仍可能进入结果。
- 代码使用 `LIKE '%query%'`，没有利用现有 `notes_fts` 提供全文相关性和匹配片段。

本地页面核对确认：搜索弹层可打开；窄窗口下搜索入口的无障碍名称会消失；Esc 关闭后再次打开会保留关键词；当前检查未发现新增控制台错误。

## 三、用户问题

### 1. 找到但不能到达

用户点击结果后进入模块首页，还要再次寻找目标对象。对于任务、笔记和视频，这会让全局搜索退化成导航；对于书籍，无法直接进入阅读器。

### 2. 搜索过程不可判断

用户无法区分“还在查询”“没有结果”“某个数据库失败”和“所有模块均无结果”。失败被当成空结果会降低信任。

### 3. 键盘效率不足

命令面板提供了 `Ctrl/Cmd+K` 和 Esc 提示，但结果没有键盘选择模型，`/task` 与 `/note` 文案也没有完整的 Enter 执行闭环。

### 4. 结果不够相关

固定 LIMIT、无 ORDER BY、无匹配字段和无总数，无法保证最有用的结果排在前面，也无法解释为什么某条结果被命中。

### 5. 隐私边界不清晰

私密笔记标题仍可能出现在全局搜索中。即使正文被保护，标题泄露也可能暴露敏感主题。

| 优先级 | 范围 | 本轮决策 |

| P1 | 结果精确定位 | 必须完成 |
| P1 | 键盘导航与焦点管理 | 必须完成 |
| P1 | 查询竞态、加载和错误状态 | 必须完成 |
| P1 | 结果排序、计数和查看全部 | 必须完成最小闭环 |
| P2 | FTS、snippet、高亮和统一索引 | 纳入方案，视数据量分阶段实现 |

## 五、目标体验

1. 用户按 `Ctrl/Cmd+K` 或点击顶部搜索入口。
2. 弹层打开后输入框自动聚焦，空状态展示搜索范围、命令示例和最近搜索（若已实现）。
3. 输入过程中显示加载状态；最新查询完成后，结果按相关性和更新时间排序，并按模块分组显示数量。
4. 用户可用上下键选择结果，Enter 打开结果，Esc 关闭并恢复触发按钮焦点。
5. 点击任务、笔记、书籍或视频后，直接打开对应对象；搜索面板关闭，模块上下文正确。
6. 无结果时显示可操作的改写或清除入口；部分模块失败时显示明确提示和重试入口。
7. 私密笔记在锁定状态下不显示可识别标题、正文或片段。

## 六、功能规格

### 6.1 统一结果模型

结果至少包含：

```ts
type GlobalSearchResult = {
  id: string | number
  module: 'tasks' | 'notes' | 'books' | 'videos' | 'command'
  title: string
  description?: string
  matchedField?: string
  snippet?: string
  score?: number
  updatedAt?: string
  action: () => void
}
```

结果操作必须使用实体 ID，而不是只切换模块。

### 6.2 查询范围

- 任务：标题、描述；结果可打开任务详情。
- 笔记：标题、非私密正文；锁定的私密笔记默认完全隐藏。
- 书籍：书名、作者；结果可打开指定书籍阅读器或详情。
- 视频：标题、普通 URL、规范来源 URL；结果可打开指定视频详情。
- 命令：继续支持 `/task <标题>` 和 `/note <标题>`，使用 Enter 执行并在失败时反馈原因。

### 6.3 结果相关性

第一阶段至少采用确定性排序：标题完整匹配 > 标题前缀匹配 > 标题包含 > 其他字段包含；同分时按更新时间倒序。第二阶段再引入 FTS rank、snippet 和高亮。

### 6.4 状态模型

搜索 UI 至少支持：`idle`、`loading`、`ready`、`empty`、`partial-error`、`error`。任何状态不得复用“没有匹配的检索结果”作为通用文案。

### 6.5 可访问性与响应式

- 搜索入口必须有稳定 `aria-label`，不依赖隐藏的可见文字。
- 弹层使用 combobox/listbox/option 语义，提供 active descendant 或等效焦点状态。
- 结果支持键盘上下移动、Enter 执行、Esc 关闭。
- 390px 宽窗口下无横向溢出，输入框、清除按钮和结果标题可读。

## 七、非功能要求

- 所有 SQL 值继续使用参数绑定。
- 快速连续输入时旧请求不得覆盖新结果。
- 四个模块查询应并行执行或由主进程统一查询，避免不必要的串行等待。
- 首个结果目标：常用数据规模下 P95 小于 300ms；超过 300ms 必须有加载反馈。
- 私密内容不写入不必要的日志、DOM 属性或结果缓存。
- 中英文文案、键盘操作和错误路径必须有测试或验收证据。

## 八、验收标准

1. 任务、笔记、书籍、视频结果均能直接打开对应对象。
2. 上下键和 Enter 可完成结果选择与打开；Esc 关闭后焦点回到搜索入口。
3. 快速输入不会出现旧结果回退；查询失败有明确反馈。
4. 空查询、加载中、无结果、部分失败、完全失败状态文案和操作不同。
5. 结果显示模块、匹配字段或片段，并有稳定的相关性排序。
6. 锁定的私密笔记不会泄露可识别信息。
7. 窄窗口下搜索入口和弹层仍可操作、可读、可访问。
8. 现有 `/task`、`/note` 命令行为保持兼容并有失败提示。

## 九、指标与后续决策

建议在实现后记录：搜索首屏耗时、零结果率、结果点击率、各模块命中率、键盘执行率和失败率。若零结果率高，应优先改进词法归一化、同义词或 FTS；若点击率低，应优先改进结果摘要和定位动作。
